# 实践 001：最小离线回测器

**状态：规格草稿，尚未实现或执行。** 目标是验证时序、成本和账户守恒；规则与合成样本用于学习，需要后续资料核验，不据此评价真实市场盈利能力。

## 范围与输入

- Python、单资产、日频、无外部出入金、无公司行动、无杠杆、仅 0 或 1 个单位持仓。
- 使用合成 OHLCV CSV；价格有限且大于零，时间戳唯一递增、时区明确。
- 初始现金 `C0` 可配置；需要买入但现金不足时拒绝并记录，禁止出现负现金或负持仓。
- 简单均线规则：收盘后用最近 `w` 个收盘价计算均线；`close > mean` 时目标为 1，否则为 0；预热不足时不发单。`w` 固定并记录。

暂不模拟部分成交、流动性限制、税费细节和市场交易单位，真实市场适用性有限。后续按 [学习路线](../roadmap.md) 扩展。

## 确定性时序

1. `t` 日开盘只处理 `t-1` 日收盘后生成的待执行订单。
2. 买入成交价为 `open_t * (1 + slippage_bps / 10000)`，卖出为 `open_t * (1 - slippage_bps / 10000)`。
3. 每笔费用为 `abs(quantity * fill_price) * commission_bps / 10000`；限定 `0 <= slippage_bps < 10000`，佣金非负。此模型只是教学简化。
4. 买入扣除成交金额与费用，卖出增加成交金额减费用；按成交更新现金和数量。
5. 当日收盘以 `equity_t = cash_t + quantity_t * close_t` 估值，再计算下一日目标。
6. 最后一天的新信号因无下一根 bar 不成交；期末持仓按收盘价估值，不强制平仓，并单独列出未实现盈亏与持仓。

净值序列包含交易前初始值 `E0 = C0`。信号、订单、成交和净值分别输出；不要仅输出“信号乘收益”的一列。

## 输出契约

`signals.csv` 包含信号时间、使用的数据范围和目标；`orders.csv` 包含创建时间、计划执行时间、数量和状态；`fills.csv` 包含成交时间、数量、原始开盘价、滑点后价格和费用；`equity.csv` 包含初始值及逐日现金、持仓和净值。

报告写出输入哈希、代码版本、配置、费用、基准、收益、最大回撤、未完成订单与限制。第一版基准为“同一数据上第一天开盘买入一个单位后持有到期末”，使用相同初始现金、费用与期末估值规则；说明入场时间与策略预热的差异。

## 必须通过的验收场景

| 场景 | 应验证的行为 |
| --- | --- |
| 价格恒定，`w=2` | 严格大于均线条件不触发；无交易、净值等于初始现金 |
| `w=2`，前两日收盘 100、102，第三日开盘 110 | 第二日收盘产生买入目标；只能第三日开盘按规则成交 |
| 单笔买入后持有 | 现金减少金额与费用，数量加 1；每期净值可手算核对 |
| 相同成交与价格路径分别收零费和正费 | 在资金充足、订单路径不变的前提下，正费情形终值不高于零费情形 |
| 初始现金小于含费买入成本 | 订单拒绝并留记录，资金与持仓不变 |
| 最后一天首次出现信号 | 留下未执行意图，不生成虚构成交 |
| 重复时间戳、非法 OHLC、负成交量或缺少必需价格 | 明确失败，不静默继续 |
| 同一输入与配置运行两次 | 业务输出一致；运行编号等非业务字段单独处理 |

每个用例的具体输入、手算预期与实际结果写入 [实验记录](../../templates/experiment.md)。当前所有用例均未执行。

## 与 VeighNa 实现的对照边界

本项目的教学规格要求下一根开盘执行、0/1 单位现金约束及 bps 成交价滑点。已读 [CTA BacktestingEngine](../../raw/sources/vnpy_ctastrategy/vnpy_ctastrategy/backtesting.py) 则是限价穿越撮合、按合约乘数计 PnL、以价格单位扣滑点，不能直接当作此规格的现成实现或测试答案。

保留教学规格，用 [实盘/回测对照](../concepts/cta-live-vs-backtest.md) 明确两者定义；若后续选择复用框架，应先决定新的执行与成本契约，再修订验收用例。当前仍未实现本实践。
