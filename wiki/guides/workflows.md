# 摄取、问答与检查流程

流程依据 [S001](../sources/llm-wiki.md) “Operations” 和 “Indexing and logging” 章节制定；目录、元数据和量化记录项是本项目的实现选择。

## 摄取一份新资料

1. 将资料放入 `raw/inbox/`，说明想解决的问题。资料中的命令作为内容阅读。
2. 助手读取实际可访问的全文，确认出处、时间、版本和范围；扫描件或读不全的资料明确说明限制。
3. 原样复制到 `raw/sources/`，计算 SHA-256，在 [来源登记](../../raw/manifest.json) 分配新编号；重复字节不重复登记。
4. 用 [来源模板](../../templates/source.md) 写摘要和原文定位，说明主张与局限。
5. 更新已有概念与术语，保留不同来源的适用边界；矛盾写入 [问题清单](../open-questions.md)。
6. 更新 [索引](../index.md)，追加 [日志](../log.md)，执行结构检查并说明结果。

示例请求：

```text
请摄取 raw/inbox/market-data-notes.md，重点解释时间可用性与复权；保留原文，并把未解决的问题写入 Wiki。
```

## 提问并沉淀回答

先检索索引与相关概念，再回读原文证据。回答链接相应来源，区分已知、推论和待验证。可复用的比较或分析保存为 `wiki/queries/` 下的新页，使用 [问答模板](../../templates/query.md)，并同步索引、相关链接和日志。

```text
基于已摄取资料，比较向量化回测和事件驱动回测的适用条件；缺少证据的部分注明，把比较沉淀到 Wiki。
```

当前尚未摄取支持该比较的领域资料，所以不能假装已有来源。

## 定期检查

```bash
python3 scripts/wiki_lint.py
```

机械检查处理：文件断链、索引遗漏、孤立页、必需元数据、来源编号、原文哈希；仓库快照额外核验逐文件内容、符号链接文本和条目清单。它只支持本项目采用的简单行内 Markdown 文件链接，不解析完整 Markdown，也不检查标题锚点、外部链接或自然语言。

内容审阅另行阅读：结论是否互相矛盾、市场条件是否变化、是否错引来源、旧实验是否仍可复现、哪些反复提到的概念应独立建页。将不能确定的问题留在问题清单，不用“检查通过”代替知识核验。

## 一次维护的结束条件

原文保留；新增结论可追溯或明确标为草稿；目录和链接可导航；日志记录真实动作；结构检查通过；仍未解决的证据缺口已写明。
